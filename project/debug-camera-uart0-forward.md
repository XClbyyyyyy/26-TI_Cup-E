# 调试记录：camera-uart0-forward

状态：OPEN

## 现象
限制摄像头原始 POS 数据经 UART0 每秒转发一次后，上位机不显示持续变化的摄像头数据。

## 初始假设
1. 首次转发须等待系统时间达到 1000ms，观察窗口过短。
2. UART1 没有生成完整帧，函数在 `uart1_frame_ready == 0` 处提前返回。
3. 系统毫秒计时未递增，导致 1000ms 条件始终不满足。
4. UART0 正在正常工作，但转发条件未满足。

## 运行证据
用户提供的串口输出：
- 初始 `u1:0 len:0 seq:0`，随后出现 `POS,1,0,182,395,914`。
- 后续稳定为 `u1:2 len:19 seq:1`，坐标为 `x:-138 y:155`。
- `u1` 是 UART1 收到换行并形成完整帧的计数；它停在 2，说明 MCU 确实接收到两帧完整摄像头数据，但之后没有再收到以换行结束的新帧。
- `seq:1` 说明第二帧已通过序号检查并更新了坐标。UART0 及系统定时器正常。

## 当前结论
限制 UART0 转发频率没有阻断 UART1 接收。当前问题位于摄像头输出侧、摄像头工作模式，或摄像头至 MCU 的 UART1 物理链路；需要比较 state=0 与 state=2 时 `u1` 是否持续增长。
