问题与解决方案
1.XY轴步进电机的脉冲数与运动距离的比例不同的问题。

  由于整个装置用的步进电机和传动装置是完全一样的，一开始用的是负责硬件的同学给的比例，具体数值忘了大概是八十多个脉冲对应走1mm。
  但是实际上操作两轴分别走完统计所需脉冲数发现完全不同，短边比例为91而长边只有79，将比例修改之后显著提升了抓取拼图的命中中心的概率。
2.视觉零点与机械零点不同的问题。
  这没什么，量一下两者相差的距离，计算的时候给个固定补偿就好了。
3.镜头不平行于写字机水平面导致的误差问题。
  实测的时候发现，给Y轴一个固定的补偿，拿和放的过程中都存在离原点近的拼图，电机移动距离偏大；离原点远的拼图，电机移动距离偏小的问题。
  后来想了想，认为是镜头由一根水平横杆从侧边延伸出去保持在装置中心，没有支撑导致细微偏移的问题。
  于是多尝试几次，找到了个很适合的线性补偿公式套进去并加上边界保护，实现每次抓取肉眼看都在中心，很完美了。
局限性
1.虽然学了FreeRTOS但是先前没实际跑过项目不敢用，实际上四个电机的运动看似同步其实中间间隔了2ms。
  但实际上由于硬件将四个轴的电机接在一个UART串口，而我用不同地址给不同电机传输指令必须要有时间间隔。
  而且本来就不是不同系统，所以也没必要用FreeRTOS（说了一大段废话）。
2.由于装置运动所需的数据是视觉部分一次性传输给我的，所以一次完整的拼图过程中间没有任何其他事项需要处理，因此电机的各步运动之间是阻塞式delay。
  也是根据距离和给定的运动速度计算需要delay的时间并尽量减少了垃圾时间，比如X和Y轴共用一个两者时间较长的delay这种。
  但其实张大头的步进电机似乎可以做到缓存指令并分布执行，不过没试过且这样做同一电机各布运动之间没有时间余量，其实也并非好事。
